How the ESPRIT IP is added to the block design

The ANTSDR E310 LoopBack pipeline with the I-UESPRIT and M-ESPRIT direction-of-arrival estimators (Li et al., IEEE TIM vol. 74, 2025, Art. 2003209). This page covers where the ESPRIT block sits in the Vivado block design, how it is connected, and what each build script does to get it there.

The key idea: ESPRIT is not a new cell in the block design. It lives inside the existing custom IP gnss_passthrough, which went from v1.1 to v1.2. In the block design the wiring, the cell and its AXI address (0x43C0_0000) are all unchanged. The only new block-design lines are two IP parameters, ENABLE_IUESPRIT and ENABLE_MESPRIT, which choose which estimators are built.

1. Where it sits in the block design

The block design, built by Source/BlockDesign/system_bd.tcl, is the standard Analog Devices AD9361 design plus one custom cell, gnss_passthrough. That cell sits between the AD9361 interface core and the TX data path. It sees both RX channels, drives the TX data, and has an AXI4-Lite register port on the processor's interconnect.

The RX tap is the key connection. In system_bd.tcl the ADC pins of axi_ad9361 already feed the vendor capture FIFO. ad_connect fans the same nets out to gnss_passthrough as well, so the DMA capture path keeps working and ESPRIT sees exactly the same samples.

2. Inside gnss_passthrough: where u_doa is instantiated

All of the ESPRIT integration is plain Verilog in Source/HDL/gnss_passthrough.v. It instantiates the DOA wrapper next to the original passthrough logic and shares the AXI4-Lite port with it, using a different address range.

// Source/HDL/gnss_passthrough.v  (v1.2, abridged)
module gnss_passthrough #(
  parameter FIFO_ADDR_WIDTH = 5,
  parameter ENABLE_IUESPRIT = 1,   // build the I-UESPRIT estimator
  parameter ENABLE_MESPRIT  = 1    // build the M-ESPRIT estimator
) ( ... same ports as v1.1 ... );

  localparam [31:0] CORE_VERSION = 32'h00010002;   // v1.2

  // writes to 0x100..0x1FC go to the DOA block
  wire doa_wr = reg_wr && (reg_waddr[11:6] == 6'h01);

  gnss_doa_esprit #(
    .ENABLE_IUESPRIT (ENABLE_IUESPRIT),
    .ENABLE_MESPRIT  (ENABLE_MESPRIT),
    .MAX_LOG2_SNAP   (14)
  ) u_doa (
    .clk (clk), .rst (rst),                          // l_clk domain: RX samples
    .adc_valid (adc_valid_i0),
    .adc_data_i0 (adc_data_i0), .adc_data_q0 (adc_data_q0),
    .adc_data_i1 (adc_data_i1), .adc_data_q1 (adc_data_q1),
    .aclk (s_axi_aclk), .aresetn (s_axi_aresetn),    // AXI domain: processing + registers
    .reg_wr (doa_wr), .reg_widx (reg_waddr[5:0]), .reg_wdata (s_axi_wdata),
    .reg_ridx (s_axi_araddr[7:2]), .reg_rdata (doa_rdata)
  );

  // read mux: anything in 0x100..0x1FF comes from the DOA block
  default: axi_rdata <= (s_axi_araddr[13:8] == 6'h01) ? doa_rdata : 32'd0;

The full hierarchy path, as Vivado reports it after implementation (and as report_doa.tcl prints it):

i_system_wrapper/system_i/gnss_passthrough/inst/u_doa
                                               ├── g_iuesprit.u_core   (i_uesprit_2ant_core, if ENABLE_IUESPRIT=1)
                                               ├── g_mesprit.u_core    (m_esprit_2ant_core,  if ENABLE_MESPRIT=1)
                                               ├── u_afifo             (doa_async_fifo, clock crossing)
                                               └── u_tgen              (doa_test_gen, known-angle test source)

3. The DOA pipeline inside u_doa

What happens inside each estimator (two-antenna closed form from the paper)

moments over 2n snapshots
covariance / 4th-order cumulant→ block-floating normalise
Cp, p = 4→ closed-form ψ
2×2, regulariser μ→ CORDIC atan2
φ = arg ψ (I: 2·atan)→ θ = asin(−k·φ)
BRAM LUT, k = λ/2πd

M-ESPRIT also reports |ψ|. A real source gives |ψ| ≈ 1; noise falls off the unit circle and is flagged, which is the paper's Remark A.

4. The build flow, step by step

These are the steps you ran, in order. Steps marked ESPRIT are where the ESPRIT work comes in; unchanged steps are the original LoopBack flow.

  1. RTL sources ESPRIT
    Source/HDL/gnss_passthrough.v (v1.2), gnss_doa_esprit.v, doa_async_fifo.v, doa_test_gen.v, and the 16 core files in Source/HDL/esprit/. The list lives in one place, Source/Sim/ESPRIT/doa_files.tcl, and both simulation and packaging read it.
  2. Package the IP: gnss_passthrough_ip.tcl ESPRIT
    Packs all 20 RTL files plus the CDC constraints into Build/ip_repo/gnss_passthrough/component.xml. Vivado's IP packager turns the top-level parameters into IP options, so the IP now has user parameters ENABLE_IUESPRIT and ENABLE_MESPRIT. 
    IP_PACKAGE_SOURCES: 20 RTL files (gnss_passthrough + ESPRIT DOA)
IP_PACKAGE_OK: .../Build/ip_repo/gnss_passthrough/component.xml
  3. Create the project: create_project.tcl → system_bd.tcl ESPRIT
    The block-design script adds Build/ip_repo to the IP catalog, refuses an old v1.1 package, places the cell, sets the two parameters, wires it and maps its address: 
    # 1. guard: the packaged IP must contain the ESPRIT RTL
if {[string first "gnss_doa_esprit" $gnss_cx_txt] < 0} { error "... OLD v1.1 package ..." }

# 2. place the cell (same as v1.1)
ad_ip_instance gnss_passthrough gnss_passthrough

# 3. NEW: choose the estimators for this project (GNSS_DOA_ALGO)
ad_ip_parameter gnss_passthrough CONFIG.ENABLE_IUESPRIT $gnss_en_i
ad_ip_parameter gnss_passthrough CONFIG.ENABLE_MESPRIT  $gnss_en_m

# 4. wiring (same as v1.1)
ad_connect axi_ad9361/l_clk          gnss_passthrough/clk
ad_connect axi_ad9361/adc_data_i0    gnss_passthrough/adc_data_i0    ;# ... i0 q0 i1 q1
ad_connect gnss_passthrough/dac_data_i0 axi_ad9361/dac_data_i0       ;# ... TX back
ad_connect axi_ad9361_dac_fifo/dout_data_0 gnss_passthrough/dma_dac_data_i0

# 5. AXI address (same as v1.1)
ad_cpu_interconnect 0x43C00000 gnss_passthrough
    Console proof: GNSS_IP_CHECK: ... (v1.2) and GNSS_DOA_ALGO: mesprit (ENABLE_IUESPRIT=0, ENABLE_MESPRIT=1).
  4. Generate the block design and synthesise the IP out of context unchanged
    Vivado copies the packaged sources into antsdr_e310_gnss.gen/…/ipshared/ and synthesises system_gnss_passthrough_0 on its own, with the chosen parameters. A generate block in the RTL leaves out the disabled estimator completely. Check: CORE_VERSION = 32'h00010002 in the generated gnss_passthrough.v, and gnss_doa_esprit appearing in that run's runme.log.
  5. Synthesis, implementation, bitstream and XSA: build.tcl unchanged
    The ESPRIT CDC constraints are applied here: the packaged XDC plus gnss_passthrough_cdc.xdc section 4. Your M-ESPRIT build: BUILD_TIMING: MET, WNS 0.005 ns.
  6. Post-implementation check: report_doa.tcl ESPRIT
    Finds u_doa, prints utilisation for each estimator, checks every CDC constraint found its cells, and reports timing into the block. 
    DOA_IMPL: estimators built: M-ESPRIT
DOA_IMPL: u_doa (total)     LUT 11743  FF 7528  DSP48 56  RAMB 5
DOA_IMPL: g_mesprit.u_core  LUT  9460  FF 5882  DSP48 50  RAMB 4
  7. Firmware: build_software.py, adding gnss_doa.c ESPRIT
    The driver reads DOA_CAPS at 0x43C0_0194 to learn which estimators are in the bitstream. It runs the self-test at boot and adds the doa… console commands.
  8. Boot: FSBL + bitstream + ELF → BOOT.BIN on SD → PuTTY unchanged
What went wrong earlier, and the guard added for it: your first build used the old v1.1 package that was still in Build/ip_repo. The block design looked identical, because the cell, ports and address are the same, so nothing failed, but the bitstream had no ESPRIT logic (0 DSP48 under gnss_passthrough). system_bd.tcl now stops with "OLD v1.1 package" in that case.

5. Three project variants from one IP

The packaged IP is the same for all three. Only the two block-design parameters differ, chosen by the environment variable GNSS_DOA_ALGO when the project is created:

GNSS_DOA_ALGOProject folderENABLE_IUESPRITENABLE_MESPRITSelf-test on board
mespritVivado/Project_MESPRIT019 checks
iuespritVivado/Project_IUESPRIT108 checks
unset / bothVivado/Project1111 checks

You can also see and change the same setting in the Vivado GUI: double-click the gnss_passthrough cell to open Customize IP. GUI edits are lost the next time create_project.tcl runs, though, so use the variable.

6. The software view: same AXI port, new address range

0x43C0_0000 – 0x43C0_00FF

Original passthrough registers: ID GCP1, version (now 0x00010002), control, RX counters, CRPA coefficients. Unchanged apart from the version.

0x43C0_0100 – 0x43C0_0194 new

ESPRIT DOA: ID DOA1, CTRL (enable, test source, p, window, averaging), μ, k = λ/2πd, CAL, test generator, results for each estimator (φ, ψ, θ, degrees, mean, mean²), status, and CAPS.

When DOA_CTRL.enable = 0 (the reset value) the DOA block is held in reset, and the design behaves exactly like v1.1.

7. How to see it yourself in Vivado

  1. Block design: open the project, then Open Block Design. gnss_passthrough looks the same as before. Double-click it to see ENABLE_IUESPRIT and ENABLE_MESPRIT.
  2. Inside the IP: Open Implemented Design, then in the Netlist pane expand system_i → gnss_passthrough → inst → u_doa. Right-click → Highlight Leaf Cells shows where the ESPRIT logic was placed on the device.
  3. Numbers: in the Tcl console, open_run impl_1 then source Vivado/Scripts/report_doa.tcl.
  4. Address: the Address Editor tab shows gnss_passthrough/s_axi at 0x43C0_0000.

8. Why it was integrated this way

Block design untouched

No new AXI slave, no new address, no rewiring. The ADI script flow and the firmware's base address keep working, and the risk to the proven LoopBack path is small.

Same samples as the passthrough

ESPRIT taps the RX nets that already exist, so it measures exactly what the CRPA insertion point sees, on the same clock.

Receive-only

The DOA block never drives TX or the DAC mux. A fault in ESPRIT cannot change what is transmitted.

One clean clock crossing

Heavy maths runs at 100 MHz on the AXI clock. Only capture runs on rx_clk, and a single constrained FIFO joins the two clock domains.
