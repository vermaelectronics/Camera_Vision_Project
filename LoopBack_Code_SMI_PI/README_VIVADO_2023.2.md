# LoopBack_Code_SMI_PI: space-time SMI power inversion (SMI-PI v4.1), Vivado / Vitis 2023.2

> **v4.1.5** (this version): gated adaptation (filter bypassed with no jammer),
> RX2 input normalisation, image taps for 50 dB jammers, output make-up gain,
> a new default RF profile that carries **BeiDou B1I and all of GLONASS**
> (1582.5 MHz, 61.44 MS/s), FIRs kept off, a radio guard, faster TX start,
> `gnss_report?` and CSV output.
> **What changed and why: `README_SMI_PI_v4.1.md`.**
> **Build commands to BOOT.BIN: `BUILD_STEPS.md`.**
> **PuTTY tests and the report template: `TESTING_PUTTY.md`.**

> commands, registers), the v4.1 files win.

This project was first built with Vivado/Vitis 2026.1 and the Analog Devices
`hdl_2026_r1` library. This version builds with **Vivado/Vitis 2023.2** on
Ubuntu 22.04.

## Build

```bash
source /tools/Xilinx/Vivado/2023.2/settings64.sh
source /tools/Xilinx/Vitis/2023.2/settings64.sh
source /tools/Xilinx/Vitis_HLS/2023.2/settings64.sh
cd LoopBack_Code_SMI_PI
./Automation/Linux/build_all.sh --jobs 16
```

`build_all.sh` loads the 2023.2 Vivado, Vitis and Vitis HLS `settings64.sh`
itself when the tools are not on PATH (searched in `XILINX_INSTALL_DIR`,
`/tools/Xilinx`, `/opt/Xilinx`), so the `source` lines above are optional.

## Previous version: SMI-PI v4.0 space-time anti-jam (bitstream v4.0)

### Why v4

Bench test of v3.1.0 (one weight): with a 15 dB continuous jammer the
receiver kept 5 GPS / 3 GLONASS / 6 Galileo at C/N0 ~36 dB-Hz (cold start
47 s); at 20 dB, and with a wideband jammer, every satellite was lost. Three
causes, all fixed here:

1. **One weight cannot null a wideband jammer.** `y = x1 - a*x2` matches the
   two receive paths at one frequency only. Across 50 MHz the RX1/RX2 ratio
   changes (cable lengths, antenna spacing, the two AD9361 analog filters,
   reflections), so the null is shallow. Simulated at 50 MS/s, jammer 30 dB
   above the noise filling the band:

   | path difference between RX1 and RX2 | one weight (v3) | **v4, 31 taps** |
   |---|---|---|
   | 0.5 ns cable + 2 % filter mismatch | 29.5 dB | **48 dB** |
   | 3 ns cable (~60 cm) | 12.9 dB, satellites -12 dB | **41 dB**, satellites ~0 dB |
   | reflection -6 dB, 50 ns later | 5 dB | **38-40 dB** |
   | CW tone | 55 dB | 46-64 dB |

   12.9 dB of suppression against a 20-30 dB jammer is exactly "all
   satellites gone".
2. **The bitstream was timed for 30.72 MS/s, but the board ran at 50 MS/s.**
   In 2R2T mode the AD9361 data clock is 4x the sample rate. The 8 ns rx_clk
   constraint (vendor value) covers 30.72 MS/s (122.88 MHz); 50 MS/s is
   200 MHz, outside what Vivado checked. v4 constrains rx_clk at 4 ns
   (61.44 MS/s) and moves the filter off that clock entirely.
3. **The GUI switched both channels to the AD9361 slow-attack AGC.** Two
   independent AGCs step the gains apart and break the null. v4's matched
   gain loop now checks every 200 ms and puts both channels back to the same
   manual gain, with a console message.

### What it is

    axi_ad9361 RX1,RX2 ─► gnss_passthrough ─ m_axis_smi ─► smi_fifo_in (async) ─► smi_pi_0
                          gnss_passthrough ◄─ s_axis_smi ◄─ smi_fifo_out (async) ◄─┘
                          gnss_passthrough ─► axi_ad9361 TX1      (CONTROL[5] = 1)
                          gnss_passthrough AJ_W/AJ_COMMIT ─ aj_wts[1023:0] ─► smi_pi_0/wts
       ARM: RX DMA capture (4096 samples) ─► gnss_aj_math.c ─► 31 weights ─► AJ_W ─► commit
       smi_pi_0, both FIFOs' core side: sys_cpu_clk 100 MHz.  gnss_passthrough: l_clk (4 x fs).

- **FPGA filter** (`Source/HLS/smi_pi`, IP `smi_pi` 2.0): 16 taps on RX1 and 16
  on RX2, `y[n] = x1[n-8] - sum_{k!=8} a_k x1[n-k] - sum_k b_k x2[n-k]`. The
  RX1 tap at delay 8 is fixed at 1 (power inversion), so the output can
  never be turned down as a whole and with no jammer it is RX1. One sample
  per clock at 100 MHz (II=1), 93 multipliers (3 per complex tap).
  The RX2 taps follow the frequency-dependent RX1/RX2 ratio across the band;
  the RX1 taps cancel a reflected copy of the jammer from another direction.
- **Weights on the ARM** (`gnss_aj_math.c`): the exact SMI solution of the
  space-time power-inversion problem from one 4096-sample capture of both
  channels: 63 lag sums + edge terms give the exact 32x32 sample covariance,
  complex Cholesky in double precision. Diagonal loading = the noise power,
  estimated from the canceller's own output and iterated (no `gnss_smi_load`
  any more). RX1's own taps get 4x the loading so they do not start
  predicting the satellites away. ~100-200 updates per second; a jammer that
  appears is nulled in 1-2 updates (~10-20 ms).
- **Jammer indicator** (`gnss_aj.c`): J/N from the learned noise floor,
  suppression and residual measured with the weights that were actually
  running (out-of-sample), jammer bandwidth and centre frequency from the
  lag correlations. Printed on the console:

      [AJ] *** JAMMER ON ***  J/N +30.1 dB, WIDEBAND, fills the whole 50.0 MHz band (~48.8 MHz seen), RX gain cut 7 dB, suppression 36.8 dB, residual +0.3 dB
      [AJ] JAMMED  J/N +30.0 dB  suppression 36.9 dB  residual +0.3 dB | WIDEBAND, fills the whole 50.0 MHz band | RX 65/70 dB  TX att 70.0 dB | 165 upd/s
      [AJ] jammer OFF after 4.5 s (peak J/N +30.4 dB)
      [AJ] *** JAMMER ON ***  J/N +50.1 dB, CW tone at +3.0 MHz (RF 1587.5 MHz), RX gain cut 17 dB, suppression 57.1 dB, residual +0.8 dB

  (from the host test of the firmware against a simulated radio). Residual
  ~0 dB = the jammer is fully removed; above 3 dB for a second prints a
  WARNING with what to check.
- **Automatic, nothing to tune:** at boot the firmware sets the RF profile
  (`gnss_band=1`: LO 1584.5 MHz RX and TX, 50 MS/s, 56 MHz, which carries GPS,
  Galileo, GLONASS G1 and BeiDou B1I), switches both RX gains to the matched
  loop and starts the anti-jam engine. `gnss_tx=1` is then the only command
  needed (it also turns anti-jam on, unless you switched it off with
  `gnss_smi=0`).

### Test it the same way as before

1. Boot, wait for `ANTI-JAM ... ON`, then `gnss_tx=1`, `tx1_attenuation=70000`.
2. Jammer off: note satellites and C/N0 (`gnss_aj?` shows `jammer: none`).
3. Jammer on at 15, 20, 25, 30 dB, CW and wideband: note satellites, average
   C/N0, the `[AJ]` line (J/N, suppression, residual).
4. Same steps with `gnss_aj_mode=2` (the old single weight) for comparison,
   then `gnss_aj_mode=0` again.

### Lock time

A receiver's **cold start** needs the satellites' ephemeris, which is
broadcast in 30 s frames (subframes 1-3, 18 s minimum after bit sync); that
is why your cold starts were 31-36 s without a jammer. No anti-jam processor
can make a cold start shorter than that. What v4 changes is that a jammer
should no longer add to it (your 47 s cold start with 15 dB was most likely
the lower C/N0 slowing navigation-data decoding): the null forms within
~10-20 ms of the jammer appearing, faster than the receiver's tracking loops
notice. For under 20 s
use the receiver's hot start (ephemeris kept: 4 s in your test) or warm
start with valid ephemeris/almanac (A-GNSS).

### Limits

- Two antennas null ONE jammer direction (plus its reflections). A second
  jammer from another direction, or a satellite in the jammer's direction,
  is not separable.
- The 12-bit ADC: a jammer more than ~60 dB above the noise forces gain cuts
  that push the satellites towards the quantisation noise (v3.1.0 table
  below still applies).
- IQ imbalance images of a strong wideband jammer are not cancelled by a
  linear filter (AD9361 quadrature tracking keeps them ~50 dB down).

## Previous version: one-weight SMI-PI (bitstream v3.0 / v3.1.0)


This folder is the **SMI-PI** variant: closed-form ("sample matrix
inversion") power inversion. It has no PI-NLMS core (`LoopBack_Code`) and no
PL-NPI core (`LoopBack_Code_PL_NPI`). Same board, same gnss_passthrough
datapath, same build flow; only the processing block differs.

    axi_ad9361 RX1,RX2 ─► gnss_passthrough ─ m_axis_smi ─► smi_pi_0/s_axis_x
                          gnss_passthrough ◄─ s_axis_smi ─ smi_pi_0/m_axis_y
                          gnss_passthrough ─► axi_ad9361 TX1   (when CONTROL[5] = 1)
                          smi_load     ─► smi_pi_0/load      (register 0x48)
                          smi_adapt_en ─► smi_pi_0/adapt_en  (~CONTROL[6])
                          smi_rst_n    ─► smi_pi_0/ap_rst_n
                          smi_pi_0/wt_band ─► STATUS[21:20]
                          axi_ad9361/l_clk ─► smi_pi_0/ap_clk

### Algorithm

Power inversion with the reference element's weight held at 1: minimise the
output power subject to w1 = 1. For two elements the optimum is closed form
(Compton's power-inversion solution w ~ R^-1 e1, normalised):

    R12 = E[x1 conj(x2)]     R22 = E|x2|^2     (averaged over 2^10 samples)
    a   = R12 / (R22 + L)
    y   = x1 - a * x2

PI-NLMS and PL-NPI are LMS algorithms that iterate towards this same optimum
one small step per sample. Computing it directly gives:

- **Optimum SINR, fast.** It converges in about one averaging window
  (1024 samples, 33 us at 30.72 MS/s) whatever the jammer power.
- **No noise cancelling, no gamma.** RX1's weight is fixed at 1, so the core
  cannot lower noise (and the GNSS under it) by turning the output down. With
  no jammer, R12 ~ 0, a ~ 0 and the output is RX1. `L` (default 16 LSB^2)
  only keeps the division well-behaved; it does not decide what is cancelled.
- **Timing.** The only state carried between samples is three 36-bit
  accumulators (A <- A + p - A>>K). `a` is computed from the previous
  average and never fed back, so the divider and both complex multiplies are
  plain pipeline stages. No multiplier sits in a feedback loop, which is what
  broke timing in PL-NPI (-20 ns).

C simulation (`Source/HLS/smi_pi/testbench.cpp`, run by the build): CW jammer
on [1, 0.6-0.5j], weak BPSK "satellite" on [1, -0.2+0.9j], +-20 LSB noise per
element. SINR measured by correlation; the optimum for this geometry is
-6.83 dB.

| jammer on RX1 | RX1 alone | PL-NPI gamma 1 | PL-NPI gamma 1e8 | **SMI-PI** |
|---|---|---|---|---|
| none | -8.9 dB | -30.2 dB | -10.0 dB | **-9.6 dB** (output level = RX1) |
| 60 LSB | -20.3 dB | -12.7 dB | -10.5 dB | **-7.2 dB** |
| 600 LSB | -40.0 dB | -14.3 dB | -7.0 dB | **-6.8 dB** (jammer null -52.7 dB) |
| 2000 LSB | -50.5 dB | -9.4 dB | -7.0 dB | **-6.8 dB** |
| 40 dB null reached | | ~500 samples | ~1500 samples | **< 1000 samples** |

The 0.7 dB loss without a jammer comes from the test "satellite" being far
stronger than real GNSS (-9 dB SNR here, -20 to -30 dB in reality); for real
GNSS it is negligible.

- Sources: `Source/HLS/smi_pi/` (`smi_pi.cpp`, `smi_pi.h`, `testbench.cpp`,
  `build_hls.tcl`).
- Stage `smi` runs `vitis_hls -f build_hls.tcl`: C simulation (4 scenarios),
  C synthesis, then **fails** if the achieved II is worse than 2 or the
  estimated clock is above 8 ns, then exports `antsdr:gnss:smi_pi:1.0` to
  `Build/ip_repo/smi_pi` (with `smi_pi_csynth.rpt`). Overrides:
  `SMI_PI_CLK_NS=7` (more margin), `SMI_PI_II=<n>`, `SMI_PI_K=<k>` (averaging
  2^k samples, default 10), `SMI_PI_SKIP_CSIM=1`.
- Registers: `CONTROL[5]` (0x0C) enables it, `CONTROL[6]` freezes the weight,
  `0x48` is L (reset 16, reads back the value in use), `STATUS[18]` reads the
  enable back, `STATUS[21:20]` the |a| band (0: <0.25, 1: <1, 2: <4, 3: >=4;
  0 means nothing is being cancelled), `STATUS[10]` a dropped sample pair
  (must stay 0). VERSION reads 3.0.
- Console: `gnss_smi=1`, `gnss_smi=0`, `gnss_smi_load=<n>`,
  `gnss_smi_freeze=1/0`, `gnss_smi?`, `gnss_rx_gain?`, `gnss_rx_gain=<dB>`,
  `gnss_rx_agc=0/1/2`.

**RX gain with SMI-PI (firmware v3.0.5, `gnss_smi_agc.c`).** The AD9361 AGC
runs RX1 and RX2 independently. Each unequal gain step changes the RX1/RX2
ratio the weight was computed for. In the C model with the real HLS core, the
jammer residual reached -1 dB during such steps, against -50 dB when both
channels step together. `gnss_smi=1` therefore switches to **matched
automatic gain** (`gnss_rx_agc=2`):

- Both channels are always set to the same manual gain.
- Every 5 ms (v3.1.0; 20 ms before) the firmware reads 256 snapshot samples
  per channel.
  - **Fast attack:** a peak above 1850 of 2047 lowers both gains by up to
    12 dB per step. A jammer 80 dB above the noise is absorbed in ~20 ms; it
    took ~200 ms before.
  - **Fast release:** 20 ms below 1000 raises both gains in one step sized
    from the peak, back to the reference in ~100 ms (~3 s before). The
    reference is the clean gain when the loop started, or `gnss_rx_gain=`.
  - **ADC loading:** the jammer is held at ~1450 of 2047 (~1200 before), so
    less ADC range is wasted.
- **TX level hold:** while the gain is G dB below the reference, TX1
  attenuation is lowered by G dB. That is at most 50 dB (30 dB before) and
  never below 30 dB absolute attenuation, so the retransmitted GNSS level
  does not drop. It is only applied while TX1 transmits, SMI-PI is on, and
  the output is no louder than the clean output +3 dB. A jammer that is not
  nulled is therefore never amplified. `gnss_smi=0`, `gnss_tx=0` or a new
  `tx1_attenuation=` hands control back to the operator's value.

**Core v3.1.0: rounded output.** `y = x1 - (a*x2 >> 16)` floored `a*x2`. That
put a +0.5 LSB DC offset and extra quantisation noise on every output sample.
It mattered once the gain loop had cut the RX gain for a strong jammer and
the satellites were only a few LSB. Now `a*x2` is rounded. C model with the
real HLS core, CW jammer held at ~1200 LSB, output SINR (dB) by gain cut (=
jammer increase):

| gain cut | 0 | 20 | 30 | 40 | 50 dB |
|---|---|---|---|---|---|
| v3.0 (floor) | -6.6 | -7.2 | -10.6 | -18.6 | -27.9 |
| **v3.1.0 (rounded)** | **-6.6** | **-6.9** | **-9.3** | **-16.4** | **-25.9** |

At a 40-50 dB cut the jammer is ~77-87 dB above the receiver noise, which
then lies below the 12-bit ADC's own quantisation noise. That is the
hardware limit; no weight can remove it. "80 dB" in CRPA data sheets is
usually J/S (jammer to satellite). GPS is ~28 dB below the noise in 18 MHz,
so J/S 80 dB is a gain cut of about 15 dB here, which is well inside the
table. All 4 testbench scenarios pass; `SMI_PI_IP/` carries the same core.

The null itself needs no speed-up: −40 dB within about 8 µs of jammer
switch-on (C model, any SMI_PI_K from 8 to 10). Start `gnss_smi=1` with the
jammer off, so the reference gain is the clean one.

- `gnss_tx=1` still controls whether anything is transmitted at all, and
  starts at 89.75 dB attenuation: use `tx1_attenuation=70000` (the known-good
  level).
- Limits: two elements null ONE jammer direction. Satellites close to the
  jammer direction are attenuated with it. A wideband jammer with a
  significant inter-element delay limits the null depth of any single-tap
  canceller; more taps would be the next step.

**CDC constraint fix (all three designs).** `Source/XDC/gnss_passthrough_cdc.xdc`
now false-paths every `*ctrl_meta` synchroniser. It used to match only the
CONTROL one, so the parameter synchroniser (`mu_`/`gamma_`/`load_ctrl_meta`)
was timed as an ordinary `s_axi_aclk -> rx_clk` path.
