# LoopBack_Code: building with Vivado / Vitis 2023.2

This project was first built with Vivado/Vitis 2026.1 and the Analog Devices
`hdl_2026_r1` library. This version builds with **Vivado/Vitis 2023.2** on
Ubuntu 22.04.

## Build

```bash
source /tools/Xilinx/Vivado/2023.2/settings64.sh
source /tools/Xilinx/Vitis/2023.2/settings64.sh
cd LoopBack_Code
./Automation/Linux/build_all.sh --jobs 16
```

Outputs:

| File | What it is |
|---|---|
| `Build/Output/system_top.bit` | bitstream |
| `Build/Output/system.xsa` | hardware platform for Vitis |
| `Build/ELF/e310_gnss_app.elf` | application (JTAG development build: TX silent at start-up) |
| `Build/ELF/fsbl.elf` | first stage boot loader |
| `Build/Output/BOOT.BIN` | FSBL + bitstream + application, for the SD card |
| `Build/Logs/*.log` | one log per stage |

Build the unattended SD-card version, which **starts transmitting at power-on**
(read `SD_Image/README_SD_CARD.md` first):

```bash
./Automation/Linux/build_all.sh --defines GNSS_DEPLOY_AUTO_TX
```

Run only some stages, for example after editing only the firmware:

```bash
./Automation/Linux/build_all.sh --from sw --to boot
```

The stages are `vendor, libip, ip, project, build, sw, fsbl, boot`, which you can also give as 1–8.

To open the generated project in the GUI, run `vivado Vivado/Project/antsdr_e310_gnss.xpr`.
To open the software workspace, run `vitis -classic -workspace Vitis/Workspace`.

## What changed for 2023.2

| Area | Change | Why |
|---|---|---|
| `Vendor/ADI_hdl_2023_r2/` | **New.** ADI `hdl_2023_r2` release (commit `d146370`), library and Tcl helpers only. | `hdl_2026_r1` targets Vivado 2025.1+. `hdl_2023_r2` is ADI's release built and tested with 2023.2, and it has every IP and parameter `system_bd.tcl` uses. |
| `Vivado/Scripts/create_project.tcl` | Warns if not run under 2023.2. Uses the bundled `auto_timing_fix_xilinx.tcl` when the vendor tree has none, and adds it to `utils_1` itself. | `hdl_2023_r2` predates that script and its `adi_project_files` does not register it. |
| `Vivado/Scripts/auto_timing_fix_xilinx.tcl` | **New**, copied from ADI `hdl_2026_r1` (ADIBSD licence). | Keeps the post-route timing fix that the 2026.1 build relied on. |
| `Build/ip_repo/` | Removed, regenerated by stage 3. | It had been packaged by Vivado 2026.1, and 2023.2 cannot load IP packaged by a newer release. |
| `Vitis/Scripts/build_software.tcl` | Now the default software flow (XSCT, classic BSP). Regenerates the workspace and writes build-variant defines into `gnss_build_defines.h`. No longer asks for a linker script that does not exist. | Vitis 2023.2 still has XSCT, and its classic BSP is what the vendor no-OS firmware was written for. |
| `Vitis/Scripts/build_fsbl.tcl` | **New.** FSBL from the classic "Zynq FSBL" template. | Same reason. |
| `Vitis/Scripts/build_*.py` | Still work on 2023.2: 2023.2 passes the XSA as `hw`, not `hw_design`, and options it lacks are skipped. | Optional alternative flow (`vitis -s ...`). |
| `Source/Firmware/.../xparam_compat.h`, `gnss_passthrough.h` | Accept the classic-BSP symbol names (`XPAR_PS7_DDR_0_S_AXI_BASEADDR`, `XPAR_GNSS_PASSTHROUGH_S_AXI_BASEADDR`). | The classic BSP names some symbols differently from the 2026.1 SDT BSP. Every mapping is guarded, so the 2026.1 build is unaffected. |
| `Automation/Linux/build_all.sh` | **New.** Runs all stages on Ubuntu. | The original driver was PowerShell (`Build_All.ps1`), which was not in the archive. |
| `Vivado/Project/` | Old 2026.1 `vivado.log`/`.jou` and the generated shim removed. | Generated files. |

The HDL (`Source/HDL`), constraints (`Source/XDC`) and block design contents are unchanged.

`Vendor/ADI_hdl_2026_r1_update/` and `Vendor/MicroPhase_E310_V1/` are kept for reference. The 2023.2 build does not use them.

## Status

These changes have **not yet been built** under Vivado 2023.2. The archive was
prepared without access to the tools. The scripts were syntax-checked, and
every IP and parameter in the block design was checked against the
`hdl_2023_r2` sources. Do the first run on your PC with `build_all.sh` and
look at `Build/Logs/` for each stage. Check timing (`BUILD_TIMING: MET`) in
`Build/Logs/build.log` before trusting the bitstream: the 2026.1 build needed
the post-route fix to close timing, and 2023.2 may route differently.

`SD_Image/BOOT.BIN` is the existing image built with 2026.1. It runs on the
board whatever tools you have installed. A 2023.2 build writes its own
`Build/Output/BOOT.BIN`.
